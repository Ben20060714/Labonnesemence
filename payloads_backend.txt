PAYLOADS BACKEND - LA BONNE SEMENCE
Base API: http://localhost:5000

Structure commune des reponses JSON:

Succes:
{
  "success": true,
  "data": ...,
  "message": "Message optionnel"
}

Erreur:
{
  "success": false,
  "error": "Message d'erreur"
}

Authentification:
- Les routes privees attendent l'en-tete: Authorization: Bearer <accessToken>
- Les routes marquees "admin" exigent un utilisateur avec role "admin".
- Les routes paginees acceptent en general: ?page=1&limit=10
- Reponse paginee:
{
  "success": true,
  "data": {
    "items": [],
    "total": 0,
    "page": 1,
    "limit": 10,
    "totalPages": 0
  }
}

AUTH - /api/auth
============================================================

POST /api/auth/register
Acces: public
Envoi:
{
  "email": "user@example.com",
  "username": "nomUtilisateur",
  "password": "motdepasse8",
  "role": "user | admin"
}
Champs requis: email, username, password
Regles: email valide, password >= 8 caracteres, username entre 3 et 30 caracteres.
Reception:
{
  "success": true,
  "data": {
    "user": PublicUser,
    "accessToken": "jwt",
    "refreshToken": "jwt"
  },
  "message": "Account created successfully"
}

POST /api/auth/login
Acces: public
Envoi:
{
  "email": "user@example.com",
  "password": "motdepasse"
}
Reception:
{
  "success": true,
  "data": {
    "user": PublicUser,
    "accessToken": "jwt",
    "refreshToken": "jwt"
  },
  "message": "Login successful"
}

}

Envoi: aucun body

FILES - /api/files
============================================================

POST /api/files/upload
Acces: prive
Content-Type: multipart/form-data
Envoi:
- file: fichier, champ requis
- is_public: "true" | "false", optionnel
- legend: texte, optionnel
- usage: "gallery" | "cover", optionnel
Contraintes upload:
- taille max: 10 MB
- mimetypes acceptes: images jpeg/png/gif/webp/svg, audio mp3/wav/ogg/webm, video mp4/webm/ogg, pdf, txt/csv/json, zip, Word, Excel.
Reception:
{
  "success": true,
  "data": FileWithUploader,
  "message": "File uploaded successfully"
}

POST /api/files/upload-multiple
Acces: prive
Content-Type: multipart/form-data
Envoi:
- files: liste de fichiers, max 10
- is_public: "true" | "false", optionnel
- legend: texte, optionnel
- usage: "gallery" | "cover", optionnel
Reception:
{
  "success": true,
  "data": [FileWithUploader],
  "message": "N files uploaded"
}

GET /api/files/public?page=1&limit=10
Acces: public
Envoi: aucun body
Reception: reponse paginee de FileWithUploader, uniquement fichiers publics avec usage gallery.

GET /api/files?page=1&limit=10
Acces: prive
Envoi: aucun body
Notes: admin voit tous les fichiers; utilisateur normal voit ses propres fichiers.
Reception: reponse paginee de FileWithUploader.

GET /api/files/:id/info
Acces: public si fichier public, sinon prive
Envoi: aucun body
Reception:
{
  "success": true,
  "data": FileWithUploader
}

GET /api/files/:id/download
Acces: public si fichier public, sinon prive
Envoi: aucun body
Reception: flux fichier avec headers:
- Content-Disposition: attachment
- Content-Type: mimetype du fichier
- Content-Length: taille du fichier

GET /api/files/:id/stream
Acces: public si fichier public, sinon prive
Envoi: aucun body
Reception: flux fichier inline avec headers:
- Content-Type: mimetype du fichier
- Content-Length: taille du fichier

PATCH /api/files/:id/visibility
Acces: prive, proprietaire ou admin
Envoi:
{
  "is_public": true
}
Reception:
{
  "success": true,
  "data": null,
  "message": "File is now public"
}

DELETE /api/files/:id
Acces: prive, proprietaire ou admin
Envoi: aucun body
Reception:
{
  "success": true,
  "data": null,
  "message": "File deleted"
}

DONATIONS - /api/donations

GET /api/donations/monetbil/config
Acces: public
Envoi: aucun body
Reception:
{
  "success": true,
  "data": {
    "serviceKey": "cle-service",
    "paymentUrl": "https://www.monetbil.com/widget/v2.1/",
    "notifyUrl": "http://localhost:5000/api/donations/monetbil/notify",
    "returnUrl": "http://localhost:3001",
    "cancelUrl": "http://localhost:3001"
  }
}

POST /api/donations
Acces: public
Envoi:
{
  "donorName": "Nom du donateur",
  "donorEmail": "donateur@example.com",
  "donorPhone": "+237...",
  "amount": 1000,
  "designation": "Don CABCS",
  "description": "Description optionnelle"
}
Champs requis: donorName, donorEmail, donorPhone, amount.
Regles: email valide, amount entier >= 1.
Reception:
{
  "success": true,
  "data": Donation,
  "message": "Don prepare."
}

POST /api/donations/monetbil/notify
Acces: public, appele par Monetbil
Envoi: body JSON, form-urlencoded ou query params. Le backend fusionne req.query et req.body.
Champs possibles pour retrouver la reference:
{
  "reference": "DON-...",
  "payment_ref": "DON-...",
  "transaction_ref": "DON-...",
  "item_ref": "DON-...",
  "monetbil_item_ref": "DON-...",
  "order_id": "DON-..."
}
Champs possibles pour le statut:
{
  "status": "success | successful | paid | completed | complete | accepted | failed | failure | error | rejected | declined | cancelled | canceled | cancel",
  "payment_status": "paid",
  "transaction_status": "paid",
  "state": "paid"
}
Champs possibles pour l'id transaction provider:
{
  "transaction_id": "id-provider",
  "payment_id": "id-provider",
  "operator_transaction_id": "id-provider",
  "channel_transaction_id": "id-provider"
}
Reception:
{
  "success": true,
  "data": {
    "received": true
  }
}

GET /api/donations
Acces: admin
Envoi: aucun body
Reception:

  "success": true,

  "message": "Dons recuperes."
}
